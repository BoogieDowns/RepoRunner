RepoRunner is functionally working after the UI polish, but there is a Restart All bug.

## Bug

When I click **Restart All**, the backend starts and correctly shows `Running`, but the frontend stays stuck in `Starting`.

The frontend may actually be running, but the UI never transitions from `Starting` to `Running`.

Starting/stopping frontend manually works. The problem appears during or after Restart All.

## Goal

Fix service status handling so Restart All reliably updates frontend and backend statuses.

Do not redesign the UI.
Do not add new product features.
Do not refactor unrelated code.
Focus only on the service lifecycle/status bug.

## Expected behavior

When user clicks **Restart All**:

1. Stop frontend/backend.
2. Wait until services are actually stopped.
3. Wait until configured ports are free.
4. Start backend.
5. Wait for backend to be confirmed running or failed.
6. Start frontend.
7. Wait for frontend to be confirmed running or failed.
8. UI should show accurate statuses.

Frontend should not remain stuck on `Starting`.

## Required fixes

### 1. Make `startService` always resolve status

For each service start, status must eventually become one of:

```ts
"running" | "failed" | "unknown"
```

It must never stay stuck on `"starting"` forever.

If a port is configured:

* Mark `running` when the port becomes reachable.
* If the process exits before the port opens, mark `failed`.
* If the process survives but the port does not open within the timeout, mark `unknown` and log a helpful message.

If no port is configured:

* Mark `running` if the process survives for 3 seconds.
* Mark `failed` if it exits before that.

### 2. Improve port readiness checks

When checking local dev server ports, try both:

```text
127.0.0.1
localhost
```

Some dev servers bind differently.

Use a timeout of around 15 seconds for startup readiness, not just a very short timeout.

Add helper:

```ts
waitUntilPortIsReachable(port: number, timeoutMs = 15000)
```

### 3. Add restart sequencing

`restartAll()` should be sequential, not fire-and-forget.

Use this order:

```ts
await stopServices();
await delay(500);
await startBackend();
await waitForServiceSettled("backend");
await startFrontend();
await waitForServiceSettled("frontend");
```

Where “settled” means:

```ts
"running" | "failed" | "unknown"
```

Do not leave services in `"starting"` forever.

### 4. Check for stale status updates

Guard against old process events updating the status after a new process has started.

Add a run/session id per service if needed:

```ts
service.runId += 1;
const currentRunId = service.runId;
```

Only update status if the event belongs to the current run id.

This prevents an old frontend process exit event from overwriting the status of a new frontend process.

### 5. Add better logs around Restart All

Log these events:

```text
[system] Restarting all services...
[system] Stopping services...
[system] Backend stopped.
[system] Frontend stopped.
[backend] Starting backend...
[backend] Backend is running.
[frontend] Starting frontend...
[frontend] Frontend is running.
```

If frontend gets stuck or cannot be verified:

```text
[frontend] Frontend process is still alive, but port 3000 did not become reachable within 15 seconds.
[frontend] Status set to Unknown. The app may still be running; check the preview URL.
```

### 6. Preserve working behavior

Do not break:

* manual Start Frontend
* manual Stop Services
* manual Start Frontend again
* Start Backend
* Stop Backend
* Pull Latest
* Install
* Open Preview
* Copy logs
* Clear logs
* Edit Setup

## Acceptance criteria

After the fix:

1. Manual frontend start still works.
2. Manual backend start still works.
3. Stop Services still reliably stops both.
4. Start frontend → Stop Services → Start frontend again still works.
5. Restart All starts backend and frontend.
6. Frontend does not remain stuck on `Starting`.
7. If frontend cannot be confirmed running, it changes to `Unknown` or `Failed` with a helpful log message.
8. No service remains in `Starting` forever.
