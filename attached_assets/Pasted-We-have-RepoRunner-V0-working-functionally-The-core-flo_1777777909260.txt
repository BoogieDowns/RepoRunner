We have RepoRunner V0 working functionally. The core flow works:

* setup project
* save config
* pull latest
* install
* start frontend
* start backend
* stop services
* restart all
* open preview
* view/copy/clear logs

The important start/stop/start loop is working.

Now polish the UI only. Do **not** change the app architecture, command behavior, IPC behavior, process management, or service lifecycle.

## Goal

Make RepoRunner feel like a simple, friendly desktop control panel for noob AI app builders.

Keep it dark, clean, and practical.

Do not make it look like an IDE.
Do not add terminal tabs.
Do not add extra product features.
Do not add GitHub login, cloning, branch switching, deployment, or AI debugging.

## Main UI polish requests

### 1. Improve visual hierarchy

The current dashboard has too much empty black space and the action buttons feel too large and floating.

Make the dashboard feel more intentional:

* Put project info in a compact top header card or bar.
* Put the main action buttons in a centered card/grid.
* Put logs in a clear bottom panel.
* Keep the window usable around 1200–1600px wide.
* Avoid huge dead space.

### 2. Refine dashboard layout

Suggested dashboard structure:

```text
Top app bar:
RepoRunner logo/name on left
Project name + repo path
Status pills for Frontend and Backend
Edit Setup on right

Main content:
Left or center card: Quick actions
Right or lower card: Service status / preview info

Bottom:
App Logs panel
```

A simple version is fine:

```text
[Header]

[Project card]
[Quick Actions grid]

[Logs panel]
```

### 3. Button polish

Current buttons work, but polish them:

* Make buttons smaller and more consistent.
* Use clear primary/secondary/danger hierarchy.
* Start buttons should be primary.
* Stop Services should be danger/red.
* Pull Latest, Install, Restart All, Open Preview should be secondary.
* Disabled buttons should look disabled, not just muted.
* Add subtle hover states.
* Keep icons if already present, but do not rely on icons alone.

Suggested labels:

* Pull Latest
* Install
* Start Frontend
* Start Backend
* Stop Services
* Restart All
* Open Preview

### 4. Status polish

Status pills should be easier to read.

Use states:

* stopped: gray
* starting: amber/yellow
* running: green
* stopping: amber/yellow
* failed: red
* unknown: purple or gray

Status text should be human-friendly:

```text
Frontend: Starting
Backend: Running
```

Not lowercase if possible.

### 5. Setup screen polish

The setup screen is good. Improve it slightly:

* Make the card a little more spacious.
* Improve alignment between folder input and Choose button.
* Use friendlier helper text.
* Keep fields exactly the same.
* Do not add new setup fields.
* Make Save Configuration look like the primary action.
* Add subtle validation copy if required fields are missing.

Suggested title/subtitle:

```text
Setup RepoRunner
Save your local app setup once. Run it with buttons after that.
```

### 6. Logs panel polish

The logs panel should feel useful even when empty.

Empty state:

```text
No logs yet.
Run Pull, Install, or Start a service to see output here.
```

When logs exist:

* Use a monospace font.
* Keep source prefixes.
* Make logs scrollable.
* Keep Copy and Clear buttons visible.
* Add a small line count or “Live logs” label if easy.
* Do not add search or filters yet.

### 7. Copy polish

Make copy friendly and plain.

Use:

```text
Pulling latest code...
Install finished.
Starting frontend...
Frontend is running.
Stopping services...
Services stopped.
```

Avoid overly technical copy in the UI.

### 8. Preserve functionality

This is critical:

Do not break these working behaviors:

* saving/loading project config
* start frontend
* stop frontend
* start frontend again
* start backend
* stop backend
* restart all
* open preview
* copy logs
* clear logs
* edit setup

Do not refactor process management unless required for UI state display.

## Acceptance criteria

After this UI polish:

1. The app still works exactly as before.
2. The dashboard looks cleaner and less empty.
3. The setup screen looks more polished.
4. Buttons are easier to understand.
5. Status pills are easier to read.
6. Logs panel has a better empty state.
7. No new product features were added.
8. No core behavior was changed.
