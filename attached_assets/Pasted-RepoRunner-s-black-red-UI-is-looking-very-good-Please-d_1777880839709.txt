RepoRunner’s black/red UI is looking very good. Please do one targeted refinement to the **red meteor streak behavior only**.

Do **not** redesign the UI.
Do **not** change layout.
Do **not** change app functionality.
Do **not** change process management, logs behavior, setup behavior, or product flow.

This is only about fixing the meteor animation lifecycle.

## Problem

Right now, when I click **Start Frontend**, **Start Backend**, or otherwise activate the running-state effect:

* some meteors appear first and only begin moving a moment later
* this makes them feel like they “spawn in place” instead of entering naturally from above

Also, when I click **Stop Services**:

* some meteors stop moving and then fade away
* this makes the animation feel interrupted or artificial

## Desired behavior

### When a running state begins

When the active/running meteor effect starts:

* new meteors should appear from **above the top edge of the visible screen**
* they should already be in downward motion as they enter
* they should feel like they are falling into the scene naturally
* they should not appear stationary and then begin moving later

In other words:

* **spawn above viewport**
* **already moving on spawn**
* **fall into frame naturally**

### When a running state ends

When the effect is turned off (for example after clicking **Stop Services**):

* do **not** abruptly stop existing meteors
* do **not** freeze them in place
* do **not** fade them out mid-fall

Instead:

* let existing meteors continue their natural fall
* allow them to finish their descent and fade naturally
* simply stop spawning any new meteors

So the behavior should be:

```text
active = keep spawning meteors
inactive = stop spawning new meteors, but let existing meteors finish
```

## Visual goal

The meteor effect should feel like a continuous stream of falling signal streaks.

It should behave more like:

* a system turning the signal stream on/off
* not like individual DOM elements being abruptly paused or toggled

This will make the animation feel smoother, more physical, and more polished.

## Implementation guidance

Use best judgment, but the general logic should be:

### On activation

* begin spawning new meteors at intervals
* each meteor starts just above the visible viewport
* each meteor is already in motion from frame one

### On deactivation

* stop creating/spawning new meteors
* leave existing meteors alone
* let existing meteors complete their animation lifecycle
* remove them only after they naturally finish falling/fading

### Important

Do not make the effect too dense or busy.
Keep the current subtle cinematic feel.

## Keep all current visual qualities

Preserve:

* bright meteor head
* trailing tail
* subtle red glow
* natural downward motion
* gradual fade into the lower part of the app

Do not revert to simple red lines.

## Scope

Only fix the meteor streak lifecycle/animation behavior.

Do not change:

* header
* cards

* buttons
* logs

* layout
* product flow
* setup flow

## Acceptance criteria

After this change:

1. When the running-state effect activates, meteors enter from above the top of the screen already moving downward.
2. Meteors no longer appear stationary and only start moving a moment later.
3. When the running-state effect deactivates, no new meteors spawn.
4. Existing meteors continue falling naturally and complete their motion.

6. The effect feels smoother and more polished.
