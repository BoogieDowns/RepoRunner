We are building **RepoRunner V0**.

RepoRunner is a simple desktop app for noob AI app builders / vibe coders / solo founders who want to run local GitHub/local repo apps without Git Bash or juggling terminals.

The goal is **not** to build an IDE, deployment tool, AI debugger, or complex repo manager.

The V0 promise is:

**Import your repo once. Save the run setup once. Then pull, install, start, stop, restart, preview, and copy logs with buttons.**

## Tech stack

Use:

* Electron
* React
* Node.js
* TypeScript
* Vite

Build this as a desktop app.

## Core V0 scope

Create a desktop app where the user can configure **one local project profile** and then use buttons to:

* Pull latest code
* Run install command
* Start frontend command
* Start backend command
* Stop services
* Restart all
* Open preview URL
* View basic logs
* Copy logs
* Clear logs

## Critical technical requirement

**Stop Services must be trustworthy.**

When RepoRunner starts a frontend or backend dev server, it must be able to stop it reliably.

Use this service lifecycle standard:

1. Track the child process.
2. Kill the full process tree.
3. Verify the configured port is free.
4. If needed, kill the process using that port.
5. Never show “stopped” until verification passes.

Use:

```bash
npm install tree-kill tcp-port-used
```

Implement a small `portManager.ts` that supports:

* `isPortInUse(port)`
* `waitUntilPortIsFree(port, timeoutMs)`
* `killProcessUsingPort(port)`
* `parsePortFromUrl(url)`

For Windows, `killProcessUsingPort` can use:

```bash
netstat -ano | findstr :PORT
taskkill /PID PID /T /F
```

For macOS/Linux, it can use:

```bash
lsof -ti tcp:PORT
kill -TERM PID
kill -KILL PID
```

Only manage ports explicitly configured by the user or parsed from the preview URL. Do **not** scan or kill random ports.

## Project profile

Persist exactly one project profile locally.

Use Electron’s `app.getPath("userData")` and save a JSON file.

```ts
type ProjectProfile = {
  id: string;
  name: string;
  repoPath: string;
  installCommand: string;
  frontendCommand: string;
  backendCommand: string;
  previewUrl: string;
  frontendPort?: number;
  backendPort?: number;
};
```

## Command behavior

### Pull Latest

Run:

```bash
git pull
```

inside the saved repo directory.

Stream logs under `[git]`.

### Install

Run the saved install command inside the repo directory.

Stream logs under `[install]`.

### Start Frontend

Before starting:

* If frontend port is configured and already in use, do not blindly start a duplicate.
* Show/log a friendly warning: `Frontend port 3000 is already in use. Stop services first or free the port.`

Start the saved frontend command as a long-running process.

Use:

```ts
spawn(command, {
  cwd: repoPath,
  shell: true
});
```

Stream logs under `[frontend]`.

Mark frontend as running when:

* its configured port becomes reachable, or
* if no port is configured, the process survives for 3 seconds.

### Start Backend

Same as frontend, using backend command and backend port.

### Stop Services

Stop frontend and backend.

For each service:

1. Mark status as `stopping`.
2. Kill the tracked process tree with `tree-kill`.
3. If a port is configured, wait until the port is free.
4. If the port is still occupied, kill the process using that port.
5. Re-check the port.
6. Only mark as `stopped` if verification passes.
7. If verification fails, mark status as `unknown` and log a friendly warning.

### Restart All

Run:

1. Stop Services
2. Start Backend
3. Start Frontend

Do not automatically run `git pull`.
Do not automatically run install.

### Open Preview

Open the saved preview URL in the default browser using Electron shell.

## Service statuses

Use:

```ts
type ServiceStatus =
  | "stopped"
  | "starting"
  | "running"
  | "stopping"
  | "failed"
  | "unknown";
```

Disable duplicate starts while a service is already running or starting.

Expose a safe preload API like:

```ts
window.repoRunner = {
  selectFolder(),

  runInstall(),
  startFrontend(),
  startBackend(),
  stopServices(),
  restartAll(),
  openPreview(),

  clearLogs(),
  onLog(callback),
```

Do not expose raw Node APIs directly to the renderer.

## V0 acceptance criteria

The build is successful when:

1. User can choose a local repo folder.
2. User can save one project profile.
3. The profile persists after closing and reopening the app.
4. User can run `git pull` from the button.
5. User can run the install command from the button.
6. User can start the frontend command.
7. User can stop the frontend reliably.
8. User can start the backend command.
9. User can stop the backend reliably.
10. User can restart all.
11. User can open the preview URL.
12. User can view logs.
13. User can copy logs.
14. User can clear logs.
15. User cannot accidentally start duplicate frontend/backend processes.

## Very important constraints

Do not build:

* IDE features
* Code editor
* Terminal tabs
* Deployment
* GitHub OAuth
* Clone from GitHub
* Branch switching
* Commit UI
* AI debugging
* Multi-project workspaces
* Docker support
* Environment variable manager
* User accounts
* Cloud sync
* Plugin system

Build the simplest working V0 first.

Prioritize reliability of:

```text
Start frontend → Stop frontend → Start frontend again
```

That loop must work repeatedly on Windows.
