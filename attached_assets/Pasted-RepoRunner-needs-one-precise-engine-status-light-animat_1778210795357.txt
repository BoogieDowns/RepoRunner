This is only about fixing the **startup illumination animation glitch** when starting Frontend and Backend close together.

## Current issue

We are very close, but startup illumination is still glitchy.

If I click:

```text
Start Frontend
```

and then shortly after:

```text
Start Backend
```

the lights do not animate smoothly and independently.

The first light starts illuminating, then the second one starts, and the animation looks like it glitches / jumps / inherits timing / behaves weirdly.

## What I want

Each engine light should animate independently.

Starting one service must not affect the other service’s light animation.

## Required behavior

Example:

```text
Click Start Frontend
Frontend light begins smooth fade-on from dark to red

Wait a moment

Click Start Backend
Backend light begins its own smooth fade-on from dark to red
Frontend light continues smoothly or stays lit
```

The Backend light should not:

* jump
* snap bright
* restart the Frontend animation
* share animation progress with Frontend
* inherit the other light’s animation state
* glitch when another light is already animating

## Likely fix direction

Please inspect how the status-light animation is currently implemented.

The issue is likely caused by one of these:

* shared CSS animation state
* shared class timing
* animation not being restarted per service
* both lights using global state incorrectly
* parent component re-render interrupting animations
* React keys not forcing clean per-service animation lifecycle
* transition being applied to the whole shared component instead of per-instance lens layer

## Required implementation approach

Make the illumination animation **per-service and deterministic**.

Use one of these approaches:

### Option A: per-service animation key

Add a unique animation key / run id per service light.

When Frontend enters `STARTING`, only the Frontend light gets a fresh animation key.

When Backend enters `STARTING`, only the Backend light gets a fresh animation key.

Do not remount or reset the other service’s light.

### Option B: separate per-light state

Track animation phase separately for each light:

```text
frontendLightPhase
backendLightPhase
```

or equivalent.

Do not use one shared active animation state for both.

### Option C: CSS transition based on per-light custom properties

If using CSS variables, make sure each light has its own independent variables and transition state.

The light should transition smoothly from:

* off/dim state
* to active red illumination

without sharing animation progress.

## Important animation rule

When a service enters `STARTING`, its light should always begin from the same visual starting point:

```text
dark / low glow
```

and smoothly ramp to red.

It should not begin from another light’s current brightness.

It should not skip to a midpoint.

It should not snap.

## Preserve timing

Keep the startup fade-on slow and physical.

Use approximately:

The timing is not the main problem now. The problem is independent animation consistency.
