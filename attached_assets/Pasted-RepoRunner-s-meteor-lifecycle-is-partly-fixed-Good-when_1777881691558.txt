RepoRunner’s meteor lifecycle is partly fixed.

Good:

* when I hit Stop Services, new meteors stop spawning
* existing meteors continue falling and fade out naturally

Remaining problem:

* when I start frontend or backend, new meteors still appear already visible in the top/dashboard section
* they are moving now, but they are still spawning inside the visible screen

I want a targeted fix for **spawn position only**.

Do **not** redesign the UI.
Do **not** change layout.
Do **not** change app functionality.
Do **not** change cards, logs, modal, buttons, setup behavior, IPC, or process logic.
Do **not** change the stop behavior that is now working.

## Required fix

Every newly spawned meteor must start **above the visible viewport**, not inside the visible app area.

The visual result should be:

```text
meteor is created off-screen above the app
meteor falls down into view
meteor continues through dashboard/log area
meteor fades naturally
```

## Specific implementation guidance

Please inspect the meteor creation and animation code.

For each new meteor:

### 1. Initial Y position must be negative/off-screen

Set the starting position so the entire meteor, including its tail, begins above the visible viewport.

Examples of acceptable starting values:

```css
top: -180px;
```

or:

```css
transform: translateY(-180px);
```

or if using JS animation values:

```ts
startY = -meteorLength - randomOffset;
```

The key requirement is:

```text
no part of a newly spawned meteor should be visible at creation time
```

### 2. Do not randomize initial Y into the visible area

If the current code uses random Y positions, remove that for spawn.

Allowed:

* random X position
* random delay between spawns
* random speed/duration
* random tail length
* random opacity within a subtle range

Not allowed:

* random starting Y inside the viewport
* starting at 10%, 20%, 30%, or any visible top/dashboard position

### 3. Animate from off-screen to below the fade zone

Each meteor should animate from a negative Y position to a lower end position.

Example:

```text
from y = -180px
to y = window height + 200px
```

or CSS equivalent.

It must travel through the visible page rather than appear midway down.

### 4. Keep the working stop lifecycle

Do not break the current behavior where:

* Stop Services stops new meteor spawning
* existing meteors continue falling
* existing meteors fade away naturally

That part is working and must be preserved.

## Acceptance criteria

After this fix:

1. When starting frontend/backend, no meteor appears already visible in the dashboard/top section.
2. Every new meteor enters from above the top edge of the app.
3. Meteors are already moving as they enter view.
4. Meteors continue downward and fade naturally.
5. Stop Services behavior remains correct: no new meteors spawn, existing meteors finish falling.
6. No other UI or functionality is changed.
